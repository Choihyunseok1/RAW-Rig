# RAW Rig

카메라 3대의 라이브 화면을 보면서 **버튼 한 번으로 장면별 자동 기준 측광 → 4개 설정 순차 촬영 → Bayer RAW 저장 → 무결성 검사**를 수행하는 Python / Qt 데스크톱 앱입니다. 현재 연결된 Blackfly S 두 모델에서 실제 촬영을 검증했습니다. 세 번째 카메라는 연결 후 PTP / Action0 / Bayer16 지원을 확인해야 합니다.

## 실행

현재 PC에서는 필요한 Python 패키지와 Spinnaker 런타임이 준비되어 있습니다.

```bash
cd /path/to/RAW-Rig
./run.sh
```

1. SpinView에서 카메라 획득을 멈추고 장치 연결을 해제합니다. 장치를 두 프로그램에서 동시에 제어하지 마세요.
2. **카메라 검색 → 촬영할 카메라 선택 → 선택한 카메라 연결**을 누릅니다. 지금은 2대의 라이브 화면을 확인할 수 있습니다.
3. 세 번째 카메라를 같은 GigE 네트워크에 연결한 뒤 다시 검색/연결합니다. 기본 앱은 3대 연결 후 촬영 버튼이 활성화됩니다.
4. 자동 측광 기준 카메라, 노출시간 증가 배수, 게인 증가량, 저장 폴더를 정하고 **측광 후 4개 설정 촬영**을 누릅니다.
5. 다음 장면에서도 같은 버튼을 누르면 기준을 다시 측광합니다.

새 카메라를 꽂은 뒤 **새 카메라 찾기 · 주소 설정**을 누르면 주소 검사부터 RAW 수신 검증과 자동 연결까지 진행합니다. 아래 네트워크 절차를 참고하세요.

카메라 없이 전체 과정을 확인하려면:

```bash
./run.sh --demo
```

가상 데이터는 화면과 메타데이터 모두 `simulated`로 표시되며 기본 저장 폴더도 `demo_output`입니다.

## 장면별 상대 설정

**노출시간**은 `ExposureTime`의 시간값(µs)이고, **노출 컨트롤**은 노출시간·게인 등을 조절하는 기능입니다.

버튼을 누를 때 기준 카메라 한 대에서 `ExposureAuto=Continuous`, `GainAuto=Continuous`를 일정 시간 실행합니다. 마지막 샘플들이 안정되면 자동 컨트롤을 끄고 **현재 노출시간 T₀ / 게인 G₀를 설정 1의 기준값으로 고정**합니다. 다른 카메라들은 이 기준에서 계산한 동일한 설정을 사용합니다. 카메라마다 독립적인 자동 컨트롤을 사용하지 않습니다.

기본 상대 설정은 다음과 같습니다. GUI에서 수정할 수 있습니다.

| 설정 | 노출시간 | 게인 |
| --- | --- | --- |
| 1. 기준값 · 낮은 노출시간 / 낮은 게인 | T₀ 그대로 | G₀ 그대로 |
| 2. 노출시간만 증가 | T₀ × 4 | G₀ 그대로 |
| 3. 게인만 증가 | T₀ 그대로 | G₀ + 12 dB |
| 4. 노출시간·게인 증가 | T₀ × 4 | G₀ + 12 dB |

게인은 dB 단위이므로 상대 조절은 덧셈/뺄셈입니다. 자동으로 계산한 값이 카메라들의 공통 지원 범위를 벗어나면 공통 범위로 제한하고 로그/메타데이터에 기록합니다. 제한 때문에 낮음/높음이 같은 값이 되면 촬영을 중단합니다. 수동 모드는 입력한 절대값을 사용하고 범위를 벗어나면 중단합니다.

예: 기준값 T₀=1,000µs, G₀=3dB라면 네 설정은 `1,000µs/3dB`, `4,000µs/3dB`, `1,000µs/15dB`, `4,000µs/15dB`입니다. 센서 단위 반올림을 고려한 실제 읽기값과 프레임 chunk 값을 함께 검사하고 저장합니다. 기준 노출시간 보정 배수와 기준 게인 보정량은 고급 설정에서 변경할 수 있으며 기본값은 1× / 0dB입니다.

카메라 모델이 다르면 동일한 노출시간/게인에서도 밝기·노이즈·색 응답·해상도가 다를 수 있습니다. RAW에는 각 카메라의 원래 해상도를 유지합니다. 미리보기 WB와 밝기(EV)는 표시용이며 저장할 픽셀 값에는 적용하지 않습니다.

## 화면과 설정

- 상단 **전체화면** 버튼 또는 **F11**로 전체화면을 전환합니다. **Esc**로 돌아옵니다. 일반 창의 최대화 버튼도 사용할 수 있습니다.
- 모든 버튼은 호버 시 배경·테두리 색이 바뀌고 도움말이 표시됩니다. 선택된 메뉴와 촬영 버튼도 호버 상태가 표시됩니다.
- 카메라 이미지를 한 번 클릭하면 해당 카메라가 크게 표시됩니다. 실시간 갱신은 계속됩니다. 이미지를 다시 클릭하거나 돌아가기 버튼·Esc를 누르면 이전 전체 보기로 복귀합니다.
- **촬영 메인 화면은 고정**입니다. 중앙에는 스크롤 영역을 두지 않으며 휠을 돌려도 카메라·페이지·촬영 버튼이 움직이지 않습니다. 창 폭과 높이를 함께 보고 카메라 카드의 열 수와 정보 밀도를 조절해 세 화면을 화면 안에 유지합니다.
- 큰 창에서는 오른쪽 설정 패널만 스크롤합니다. 작은 창에서는 **설정 패널** 버튼으로 오른쪽에 겹쳐 열고 닫습니다. 패널을 열어도 중앙 카메라 배치는 바뀌지 않습니다. 닫기 또는 Esc로 닫으며 촬영 계획의 상세 값도 이 패널에서 확인합니다.
- 카메라 전체 보기는 **2×2 격자**에 배치합니다. 창이 작아지면 카드 정보를 간소화해 모든 카메라 화면과 촬영 버튼을 유지하며, 이미지는 원래 비율로 표시합니다.
- 숫자 입력창과 닫힌 선택 목록 위에서도 휠은 패널 스크롤만 합니다. 입력에 포커스가 있어도 노출시간·게인·배수·촬영 모드 등이 휠로 변경되지 않습니다. 값 변경은 직접 입력·키보드·화살표 버튼·목록 선택으로 수행합니다.
- 촬영 화면 상단의 **자동 WB · 1회** 버튼은 옆 패널의 WB 기준 카메라에서 `BalanceWhiteAuto=Once`로 한 번 측정하고 자동 조절 종료(`Off`)를 확인합니다. R·B 비율은 전체 RAW 카메라 미리보기에 같은 값으로 고정 적용되며 LIVE를 꺼도 마지막 화면에 반영됩니다. 설정 화면에서도 실행할 수 있고, 조명 프로필·제한시간·R/B 값을 편집할 수 있습니다. 실패·중지 시 기존 값을 유지하고 RAW 설정 복원이 실패하면 카메라 연결을 정리합니다. RAW 원본을 보존하기 위해 측정 후 카메라 ISP와 중립 WB를 복원하고, 측정 기준·방법·값·적용 카메라를 설정/데이터셋 manifest에 기록합니다. [FLIR Once/Off 동작 설명](https://softwareservices.flir.com/BFS-PGE-23S3/latest/Model/public/AnalogControl.html)
- 촬영 설정은 창 폭에 따라 1~4열로 배치됩니다. 각 열에서 카드를 내용 높이에 맞춰 쌓으므로 짧은 카드가 옆 카드 때문에 늘어나지 않습니다. 네 촬영 설정도 넓은 화면에서 한 줄로 표시합니다.
- 검사·기록의 결과와 진행 기록은 넓은 창에서 좌우, 작은 창에서 위아래로 분할됩니다. 경계선을 드래그해 공간을 조절할 수 있으며 가로·세로 분할 비율을 각각 유지합니다. 전체 페이지는 고정되고 두 패널이 독립적으로 스크롤합니다. 결과 표는 실제 행 높이만 차지하고, 행을 선택하면 해당 카메라의 RAW 수신·CRC·PTP·예약 촬영 검증 정보를 표시합니다.
- **촬영 설정**에서 카메라 수, 촬영 수, 저장 폴더, 측광 시간·기준 보정, 안정화·워밍업·수신 제한시간, PTP 허용값·예약 시간, GPIO 라인·에지, 미리보기 WB·밝기·갱신 속도를 변경합니다.
- 촬영 화면에서 자동 기준 측광을 끄면 기존 노출시간·게인을 직접 입력할 수 있습니다. 촬영 설정에서는 네 설정의 절대값과 저장 이름을 각각 변경할 수 있습니다.
- 상단 **설정 저장 / 설정 불러오기**로 모든 설정을 JSON 파일로 저장하고 복원합니다. **검사·기록**에서 저장된 데이터셋을 재검사할 수 있습니다.

## 새 카메라 검색·주소 검사·할당

촬영 화면의 **새 카메라 찾기 · 주소 설정** 버튼은 기존 미리보기 연결을 잠시 해제하고 다음 절차를 수행합니다.

1. PC의 유선 링크와 IPv4 주소를 검사합니다. Wi-Fi와 링크가 내려간 인터페이스는 자동 할당 대상에서 제외합니다. 사용할 유선 IPv4 연결이 없으면 실제 원인을 표시하고 실패로 처리합니다.
2. SDK의 인터페이스 노드에서 카메라를 검색합니다. 초기화할 수 없는 다른 서브넷의 카메라도 인터페이스의 `DeviceSelector`를 통해 검사합니다. PC 인터페이스 MAC과 카메라 MAC·시리얼을 기록합니다.
3. PC와의 서브넷·마스크 일치, PC 주소와의 중복, 카메라 사이의 중복, ARP에서 보이는 다른 장치와의 충돌을 확인합니다. 정상 주소는 유지합니다. 다른 프로그램이 점유한 카메라나 SDK 비호환 장치는 주소를 변경하지 않습니다.
4. 주소 수정이 필요한 카메라는 PC 서브넷의 후보 주소를 검사합니다. PC·발견된 카메라·이미 배정한 주소는 예약하고, 커널 ARP 조회에서 사용 중인 주소를 제외합니다. 직접 연결되는 경로와 신규 ARP 조회의 `INCOMPLETE → FAILED` 완료를 확인한 주소만 후보로 사용합니다. 결과가 불명확한 후보는 건너뛰고 최대 16개를 검사합니다. 검증된 빈 주소가 없으면 할당을 중단합니다.
5. MAC으로 대상을 다시 선택하고 시리얼·접근 권한을 확인한 다음 SDK `GevDeviceForceIP`로 IP·마스크·게이트웨이를 함께 적용합니다.
6. 제한시간 동안 재검색하며 동일한 MAC·시리얼, 요청 IP·마스크, 중복 제거를 확인합니다. 카메라를 초기화한 뒤 연결된 장치의 IP·MAC도 다시 읽습니다.
7. Bayer16 RAW 연속 세 장을 받아 형식·크기·전송 완전성·지원되는 CRC·실제 노출시간/게인과 chunk·프레임 순서를 검사합니다. 일시적인 수신 오류는 장치를 정리하고 검사를 다시 실행합니다. PTP와 Action0 지원 여부도 보고서에 기록합니다. 실제 PTP 시차 검사는 촬영 시 별도로 수행합니다.
8. 검증을 통과한 카메라를 필요한 카메라 수까지 자동 연결하고 미리보기를 시작합니다. 기존 연결 카메라를 우선합니다. 실패한 장치는 자동 연결 대상에서 제외합니다.

주소 할당은 **임시 ForceIP**입니다. PC의 주소나 카메라의 영구 주소 설정은 변경하지 않습니다. 카메라 전원을 껐다 켠 뒤 주소가 달라졌다면 버튼을 다시 누릅니다. 자동 할당용 유선 인터페이스와 ARP 검사·재검색 제한시간은 **촬영 설정**에서 수정할 수 있습니다. 같은 NIC에 여러 IPv4 서브넷이 있고 대상을 명확히 선택할 수 없으면 임의로 이동하지 않고 실패를 표시합니다.

**검사·기록 → 카메라 주소 검사 결과**에서 각 카메라의 이전 주소, 요청 주소, 실제 주소, MAC, 할당 여부, RAW 검증, 자동 복구 기록, 원인과 다음 조치를 볼 수 있습니다. 보고서는 `~/.local/state/raw-rig/diagnostics/`에 자동 저장하며 화면에 실제 경로를 표시합니다(`XDG_STATE_HOME` 지원). **주소 검사 보고서 저장**으로 원하는 위치에 별도 내보낼 수도 있습니다. 검증용 RAW 프레임은 데이터셋으로 저장하지 않습니다. 주소가 일부 적용된 뒤 중지되면 이미 적용된 임시 주소는 유지됩니다.

SDK의 `OpenReadOnly`/`OpenReadWrite`는 해당 GenTL 호스트가 장치 핸들을 열었다는 상태입니다. IP가 정상인 장치는 이 상태만으로 거부하지 않고 실제 초기화·설정 쓰기·읽기·RAW 수신으로 제어 권한을 확인합니다. `Busy`/`ReadOnly` 장치와 열린 장치의 주소는 임의로 변경하지 않습니다.

할당 명령의 응답을 받지 못하면 명령을 다시 보내기 전에 MAC·시리얼로 요청 주소가 실제 적용되었는지 재검색합니다. ACK만 유실되었고 주소·RAW 검증이 통과하면 자동 복구 완료로 표시합니다. 재확인하지 못한 현재 주소는 **미확인**으로 표시합니다. 성공 판정은 주소 재검색과 RAW 수신 검증을 모두 통과한 경우에만 합니다.

CLI에서도 같은 주소 검사·할당·RAW 검증을 실행할 수 있습니다. CLI는 보고서를 출력하고 장치 연결을 해제합니다.

```bash
python -m rawrig network
python -m rawrig network --network-interface <camera_ethernet_interface>
python -m rawrig network --demo
```

절차는 [FLIR의 인터페이스 ForceIP·DeviceSelector 문서](https://softwareservices.flir.com/Spinnaker/latest/cpp/class_spinnaker_1_1_transport_layer_interface.html)와 [재검색 권장 절차](https://teledynevisionsolutions.zendesk.com/hc/en-us/community/posts/18216827081229-GevDeviceAutoForceIP-documentation?sort_by=created_at)를 참고했습니다.

## PTP 동기 촬영

기본 모드는 **IEEE 1588 PTP + Scheduled Action Command**입니다.

1. 모든 카메라의 PTP를 켜고 같은 기준 시계를 사용하는 Master/Slave 상태를 기다립니다.
2. Slave의 절대 offset이 설정한 한계(기본 10µs) 안에 연속 세 번 들어오는지 확인합니다.
3. 네 설정을 모든 카메라에 적용할 수 있는지 사전 검사합니다.
4. 설정별로 획득을 다시 시작하고, 카메라 시간 기준 같은 미래 시각(기본 200ms 후)의 `Action0`를 예약합니다.
5. 모든 선택 카메라의 정상 ACK, 촬영 전후 PTP 상태, 프레임 timestamp 시차(기본 최대 100µs)를 검사합니다.

PTP 시계 동기만으로 각각의 소프트웨어 트리거 실행 시각까지 같아지지는 않습니다. 이 앱은 **공통 시각 예약 촬영**을 사용합니다. 지원하지 않는 카메라나 잠금 실패 시 소프트웨어 모드로 자동 전환하지 않습니다.

현재 연결된 두 대의 실제 펌웨어에서 `GevIEEE1588`, `Action0`, 예약 큐와 1GHz timestamp를 확인했고, 최종 자동 측광 검증의 네 촬영 묶음에서 timestamp 시차가 약 **4.1~17.6µs**였습니다. 이 값은 카메라 프레임 timestamp 기준 측정이며, 광학적으로 측정한 셔터 시작 오차를 의미하지 않습니다. 세 번째 카메라를 포함한 결과는 연결 후 검증해야 합니다.

PTP 모드는 GigE 카메라들이 PTP 메시지를 주고받을 수 있는 네트워크가 필요합니다. 이 구현은 1GHz timestamp와 Blackfly S 스타일 GenICam PTP/Action 노드를 지원합니다. 다른 노드 구조를 가진 장비는 별도 어댑터가 필요합니다.

선택 가능한 보조 모드:

- **소프트웨어 트리거**: 카메라별 명령을 스레드 배리어로 병렬 전송하고 호스트 명령 시차를 기록합니다. 노출 시작 시차 보장은 없습니다.
- **GPIO 마스터 → 슬레이브**: 기준 카메라의 `ExposureActive` 출력으로 나머지를 트리거합니다. GPIO 케이블과 모델에 맞는 전기 연결이 필요합니다. GPIO 전파 지연은 보정하지 않습니다.

설정 변경 시 이전 프레임이 섞이지 않도록 획득을 중지/재시작하며 기본 1개의 워밍업 촬영 묶음을 검사 후 폐기합니다. 네 설정 전체가 동일 순간에 찍히는 것은 아니므로 장면을 유지하고 촬영합니다.

## RAW 저장과 무결성

RGB/JPEG/동영상은 저장하지 않습니다. 최대 지원 ADC 비트 깊이와 unpacked Bayer16 출력을 선택하고 SDK 버퍼에서 픽셀 값 그대로 복사합니다. ISP, gamma, LUT, 자동 WB, 지원되는 불량 화소 교정을 끄며 카메라 WB 비율은 1로 설정합니다. 적용 가능한 노드의 상태와 블랙레벨/클램핑 상태를 기록합니다. SDK의 행 패딩과 chunk 바이트는 `.raw` 픽셀 파일에 넣지 않습니다.

`BayerRG16`은 저장 컨테이너가 16비트라는 뜻입니다. 현재 두 센서의 ADC는 12비트이고 Blackfly S는 16비트 출력의 상위 비트에 ADC 값을 배치합니다. 저장할 때 비트 이동이나 정규화를 하지 않습니다. 해석에 필요한 Bayer 패턴, ADC 깊이, shape, dtype은 JSON에 있습니다.

```text
datasets/20261001_..._<id>/
  manifest.json
  COMPLETE.json
  setting_01/shot_0001/
    camera_24401040.raw
    camera_24401040.json
    camera_26315393.raw
    camera_26315393.json
    camera_<third>.raw
    camera_<third>.json
  setting_02/...
  setting_03/...
  setting_04/...
```

기본 촬영 수는 `4개 설정 × 3대 × 1회 = 12장`이며 설정별 촬영 수를 늘릴 수 있습니다. 수신 불완전 여부, 제공되는 카메라 CRC, 배열 형식/해상도/바이트 수, 프레임 ID 중복/역순, 실제 노출시간/게인과 chunk 일치를 검사합니다. 각 파일은 쓰기·fsync 후 다시 읽어 SHA-256을 검사합니다. 마지막에 모든 카메라/설정/반복 촬영 수와 파일·메타데이터 체크섬을 재검증합니다.

전체 검사에 성공해야 `COMPLETE.json`이 생성되고 임시 폴더를 최종 이름으로 바꿉니다. 오류/중단 데이터는 숨김 `.partial` 폴더와 `FAILED.json`으로 남으며 완성 데이터로 간주하지 않습니다. 어둠/포화 비율은 통계로 기록하지만 저조도 데이터의 의도된 특성이므로 해당 통계만으로 프레임을 폐기하지 않습니다.

### 자동 복구

기본 자동 복구는 2회, 재시도 간격은 400ms이며 **촬영 설정**에서 변경합니다. 전송 불완전·CRC·수신 시간 초과·오래된 프레임·chunk 설정 불일치·PTP 일시 오류가 발생하면 해당 묶음 전체를 폐기하고 획득/예약 큐 정리 → 동일 설정 재적용 → 필요한 PTP 재동기 → 모든 카메라 재촬영을 수행합니다. 이미 저장한 정상 묶음은 다시 촬영하지 않습니다. 지원되는 패킷 재전송을 켜고 표준 Ethernet MTU에 맞춘 패킷 크기와 설정 읽기값을 기록합니다.

자동 측광이 아직 수렴하지 않으면 측광 시간을 2배씩(회당 최대 30초) 늘려 다시 측정합니다. 기준 카메라·목표 밝기·노출시간/게인 상한은 유지하며 실제 측광 시간과 안정화 기록을 저장합니다. USB Z5가 포함된 묶음은 진행 중인 USB 작업을 끝낸 다음 전체를 다시 촬영하고, 실패한 묶음의 NEF는 완료 데이터셋에 넣지 않습니다. 카드에는 기존 `--keep` 정책으로 남습니다. USB 자체 실패는 임의로 재촬영하지 않습니다.

형식 미지원·제어 권한 거부·잘못된 설정·디스크 쓰기/체크섬 오류는 원인을 보존하고 중단합니다. 데이터셋 재검사는 저장된 파일을 그대로 검사하며 검사 실패를 자동으로 통과시키거나 파일을 수정하지 않습니다. 촬영 복구 기록은 그룹의 `trigger.recovery`, 측광 기록은 `meter_attempts`, 작업 예외는 자동 진단 JSON에 남습니다.

RAW 읽기:

```python
import json
from pathlib import Path
import numpy as np

raw_path = Path("datasets/<session>/setting_01/shot_0001/camera_24401040.raw")
metadata = json.loads(raw_path.with_suffix(".json").read_text())
raw = np.fromfile(raw_path, dtype=metadata["dtype"]).reshape(metadata["shape"])
# raw.shape == (height, width), RGB 변환 전 Bayer 배열
```

재검사:

```bash
python -m rawrig verify /absolute/path/to/dataset_session
```

## 센서가 다른 카메라의 비교 촬영

촬영 화면의 **노출 컨트롤 → 촬영 모드**에서 선택합니다.

| 모드 | 실제 동작 | 3대 / 반복 1회 |
| --- | --- | --- |
| 기준 1대 · 네 설정 | 기존 기준 측광과 노출시간·게인 네 조합 | RAW 12장 |
| 카메라별 기준 · 교차 촬영 | C1/C2/C3의 자동 기준을 먼저 측정·고정 → C1 기준으로 모두 촬영 → C2 기준으로 모두 촬영 → C3 기준으로 모두 촬영 | RAW 9장 |
| 교차 촬영 + 네 설정 확장 | 각 기준마다 기존 네 조합을 적용 | RAW 36장 |
| 각자 자동 측광값 · 동시 촬영 | 각 카메라에 자신의 고정된 자동 노출시간·게인을 적용 | RAW 3장 |

촬영 버튼 한 번으로 전체 계획을 수행합니다. ‘현재 장면 기준 측광’으로 계획을 미리 볼 수 있지만 **촬영 버튼은 장면 변화에 맞춰 다시 측광**합니다. 미리보기 설정 목록에서 각 그룹을 선택해 실제 조건을 확인할 수 있습니다. 모든 기준을 측정하는 동안 장면과 조명을 고정하세요. 게인은 dB, 노출시간은 µs입니다. 자동 측광의 목표 밝기·최대 노출시간·최대 게인을 변경할 수 있으며, 카메라가 해당 제어를 지원하지 않거나 상한을 제한한 경우 측광 메타데이터에 기록합니다. 동일 목표값이어도 카메라의 자체 알고리즘·시야·렌즈가 다르면 동일 밝기로 수렴하지 않습니다.

교차 촬영의 기본 범위 처리는 ‘지원 범위 밖이면 중단’입니다. 촬영 전에 전체 설정을 적용·검사합니다. ‘공통 범위로 제한하고 기록’을 선택하면 모든 대상에 동일한 제한값을 적용하고 원래 요청값도 남깁니다. 각자 자동값 모드는 카메라별 범위를 사용합니다. 설정 제한으로 서로 다른 그룹이 같은 값이 되면 계획 표와 `range_clipped` 기록으로 구분할 수 있습니다. 기존 네 설정 모드는 낮음/높음이 같아지면 중단합니다.

`capture_plan`에는 기준 시리얼, 변형 번호, 요청값, 카메라별 적용값, 범위 제한 여부가 저장됩니다. 프레임 메타데이터의 실제 설정·chunk와 계획을 대조하며, 재검사도 해당 카메라의 계획값을 사용합니다. 완료 화면의 검사 기록에는 RAW 상한 도달 비율을 표시합니다. 포화·검은 픽셀 비율은 화질 지표이며 무결성 실패 판정이 아닙니다.

```bash
python -m rawrig capture --strategy cross_reference
python -m rawrig capture --strategy cross_reference --cross-bracket
python -m rawrig capture --strategy per_camera
python -m rawrig capture --demo --strategy cross_reference --output artifacts/cross_demo
```

| IMX490 탑재 모듈 | 3.0 µm, 5.4 MP, ADC 10/12 bit, 120 dB HDR / DR 우선 조건 140 dB | 이는 센서의 HDR 모드 성능. 모듈의 HDR 합성·ISP·비선형 응답·하위 노출시간을 확인해야 단일 선형 RAW와 비교 가능 |
| Nikon Z5 | 35.9 × 23.9 mm, 24.3 MP, NEF 12/14 bit, ISO·조리개·셔터 제어 | RAW 비트 수와 DR은 동일 개념이 아님. ISO와 산업용 게인 dB의 관계는 센서별 보정 필요. 같은 조건의 EMVA DR 수치는 확인되지 않음 |

같은 노출시간·게인으로 찍으면 공통 입력 조건에서의 센서 응답을 비교할 수 있습니다. 하지만 각 센서의 최적 동작을 놓칠 수 있습니다. **교차 기준 촬영과 각자 자동값 촬영을 함께 확보**하면 공통 조건 비교와 각 장치의 실용 결과를 모두 볼 수 있습니다. 게인을 올리는 것은 광자를 늘리지 않습니다. 정지 장면에서는 포화와 움직임 제한 내에서 노출시간을 늘리는 것이 광자 확보에 도움이 됩니다. 동일 렌즈 조리개/투과율, 시야·해상도 정렬, 조명, 변환 게인·HDR 상태를 기록해야 센서 비교의 해석이 명확해집니다. 재구성 데이터셋에는 별도로 암프레임·플랫필드·black/white level·기하/방사 보정이 필요할 수 있습니다.

카메라 특성 표에서 센서 이름, 선형/HDR RAW 표기, 렌즈 조리개와 실험 메모를 저장할 수 있습니다. 변환 게인은 현재 값 유지/Low/High를 선택하며, 장치가 지원하지 않는 모드는 촬영 전에 거부합니다. **RAW 모드 표기는 사용자 기록이며 센서 HDR 모드를 변경하지 않습니다.** 표준 HDR 관련 노드가 있으면 실제 값을 별도 기록합니다. IMX490 센서 이름만으로 외부 연결 방식·드라이버·RAW 출력 API는 결정할 수 없습니다. 현재 실촬영 백엔드는 Spinnaker로 접근 가능한 카메라를 사용합니다. UVC RGB 또는 별도 MIPI/USB 드라이버 모듈에는 해당 제조사 RAW API 연결 작업이 필요합니다.

출처: [IMX429 EMVA](https://softwareservices.flir.com/BFS-PGE-27S5/latest/EMVA/EMVA.html), [IMX392 EMVA](https://softwareservices.flir.com/BFS-PGE-23S3/latest/EMVA/EMVA.html), [Sony IMX490](https://www.sony-semicon.com/files/62/pdf/p-15_IMX490.pdf), [Nikon Z5 사양](https://onlinemanual.nikonimglib.com/z5/en/15_technical_notes_08.html). IMX490 HDR 수치는 단일 선형 RAW의 DR과 직접 동일 조건 비교한 값이 아닙니다.

## Nikon Z5 USB 연동

Linux에서는 gphoto2/libgphoto2를 사용합니다. Z5는 DSLR 형태의 **미러리스** 카메라이며, libgphoto2에 USB 촬영·미리보기 지원이 등록되어 있습니다. 현재 PC에는 프로젝트 내부의 gphoto2 실행 파일과 필요한 라이브러리를 추출해 두었습니다. 다른 PC에서는 시스템 `gphoto2` 패키지와 Python 선택 의존성을 설치하세요.

```bash
python -m pip install -e '.[nikon]'
python -m rawrig nikon
python -m rawrig capture --strategy cross_reference --nikon
```

설정 화면의 **Nikon Z5 · USB 보조 촬영**에서 ‘Z5 검색 · 지원 설정 확인’을 누르면 현재 USB 포트와 노출시간·ISO·조리개·WB 등의 지원 선택지를 읽습니다. ‘Z5 USB 미리보기 갱신’은 미리보기 한 프레임을 가져오며, 클릭으로 확대·복귀합니다. 미리보기 JPEG는 임시로 읽고 데이터셋에는 저장하지 않습니다. 산업용 카메라의 라이브 미리보기는 계속 갱신되며 Z5의 USB 미리보기는 버튼으로 갱신합니다.

사진 M 모드와 수동 초점으로 고정하고 USB 데이터 케이블을 연결하세요. 다른 USB 촬영 프로그램이 장치를 점유하면 연결을 해제해야 합니다. 조리개/WB는 지원 선택지의 정확한 문자열을 입력하거나 비워 현재 값을 유지합니다. 기본값은 고정 20 ms / ISO 100이며 Z5 촬영은 선택적으로 활성화합니다. ‘노출시간·게인 환산값 따라가기’를 선택하면 지정한 산업용 카메라의 노출시간과 `ISO_base × 10^(gain_dB/20)`을 지원 선택지로 반올림해 사용합니다. 이는 **명목 환산**이며 센서 간 같은 감도/SNR을 의미하지 않습니다. 가장 가까운 값의 EV 오차가 허용값(기본 0.2 EV)을 넘으면 촬영 전에 중단합니다.

RAW 단독 NEF와 지원되는 무손실 압축을 설정하고, 자동 ISO를 해제합니다. RAW 12/14 bit는 카메라 본체 메뉴의 설정을 확인하세요. 사진마다 원본 `nikon_z5.nef`와 `nikon_z5.json`을 산업용 RAW와 같은 그룹 폴더에 저장합니다. NEF TIFF 헤더·Z5 모델·EXIF 실제 노출시간/ISO·전체 Bayer 평면 디코딩·체크섬·촬영 그룹 수를 검사합니다. 카메라 카드 파일은 삭제하지 않습니다(`--keep`). 완료/중지 시 변경한 USB 설정을 원래 값으로 복원하며 복원 실패는 기록합니다.

USB 촬영은 산업용 카메라 호출과 병렬로 실행됩니다. ‘USB 명령 시각 보정’은 양수면 Z5 호출을 늦추고 음수면 산업용 호출을 늦춥니다. PTP 예약 촬영에는 산업용 예약 선행 시간도 영향을 주므로 실제 노출 시작을 맞추려면 장면/LED 측정으로 보정해야 합니다. USB PTP는 **Picture Transfer Protocol**이며 GigE의 IEEE 1588 Precision Time Protocol과 다른 프로토콜입니다. 기록한 USB 호출 시각·수신 완료 시각·호출 간격을 실제 노출 시작 시차라고 표시하지 않습니다. 기계 셔터·AF·본체 처리 지연이 남습니다. Z5 실패를 조용히 건너뛰지 않으며 해당 묶음은 완료 데이터셋으로 공개되지 않습니다.

[libgphoto2 Z5 지원 코드](https://raw.githubusercontent.com/gphoto/libgphoto2/master/camlibs/ptp2/library.c), [gphoto2 촬영·보존·설정 명령](https://gphoto.sourceforge.io/doc/manual/ref-gphoto2-cli.html).

## RAW 노이즈 측정 · 두 단계 촬영

왼쪽 **노이즈 분석**에서 연결된 Bayer 카메라들을 측정합니다. 일반 데이터셋의 필요한 카메라 수가 3대여도 현재 연결된 1~3대만으로 노이즈 측정이 가능합니다. Nikon NEF는 이 측정 모듈의 대상이 아닙니다.

1. 렌즈 캡 등으로 모든 카메라를 완전히 차광하고 **① 차광 RAW 연속 촬영**을 누릅니다. 선택한 고정 실험 절차에 맞춰 암영상을 자동 촬영합니다.
2. 캡을 제거하고 센서 ROI에 안정되고 균일한 확산광을 비춘 뒤 **② 밝은 RAW 촬영 · 자동 분석**을 누릅니다. 방 안의 사물·움직이는 장면 대신 균일한 광원을 사용합니다. 밝은 촬영은 차광과 같은 노출시간·게인 순서를 자동 수행하고, 완료 후 분석·그래프 생성·전체 무결성 검사를 진행합니다.

측정 목적만 선택하며 실험 수치 입력은 제공하지 않습니다.

- **밝기별 곡선 · 자동 노출시간 순회**: 광원 밝기를 고정한 상태에서 100~100,000 µs 로그 간격 16단계를 자동 수행합니다. 연결된 카메라의 공통 지원 범위로 자동 제한하고, 최저 공통 게인(통상 0 dB)을 고정합니다. 단계마다 100장, 최단 차광은 픽셀 맵용 1,000장으로 카메라당 차광 2,500장 + 밝은 1,600장입니다. 실제 순회 계획을 세션에 보존하고 밝은 촬영에서 그대로 재사용합니다.
- **픽셀 분포 · 노출시간·게인 고정**: 차광 시작 시 카메라별 실제 시작값을 읽어 고정하고 차광/밝은 조건 각각 1,000장을 촬영합니다. 두 조건의 분포·노이즈 성분을 측정하며 PTC 곡선·변환 게인·전자 단위·암전류는 미측정으로 표시합니다.

논문 §2.3.2의 PTC는 조건별 **100장**, §3.1의 픽셀 오프셋·읽기 노이즈 맵은 차광 **최소 1,000장**입니다. 그림 6의 정밀 픽셀 게인 맵은 광량 단계마다 1,000장이므로 프로그램의 100장 PTC 모드와 정밀도가 다릅니다. 논문은 FLIR 모든 모델에 적용할 특정 노출시간이나 게인 수치를 정하지 않습니다.

중앙 **256×256 ROI**를 리사이즈·비닝·디모자이싱 없이 원래 Bayer 값으로 저장·분석합니다. 짝수 ROI 좌표로 CFA 색 순서를 유지합니다. 센서 전체 프레임을 수신해 검사한 뒤 ROI를 추출하므로 센서 읽기 조건은 그대로입니다. RAW 및 통계·분석 작업 공간도 촬영 전에 검사합니다. 예전 세션의 다른 ROI/반복 수는 기존 기록을 보는 용도로만 지원합니다.

계산 전에는 연결된 카메라의 라이브 화면과 분석 ROI가 보입니다. 1대는 한 화면, 2대는 두 열, 3대는 2×2 배치를 사용합니다. 클릭하면 확대하고 다시 클릭하거나 Esc로 돌아갑니다. 차광만 완료해도 잔차 히스토그램, 오프셋·픽셀 노이즈 분포/맵, 독립 표본 정밀도, 시간 추이·누적 분포의 5개 그래프를 자동 생성합니다. 결과가 생기면 **라이브 화면 / 그래프 보기**로 전환해 밝은 촬영 준비를 확인할 수 있습니다.

### 생성되는 그래프와 데이터

카메라·고정 게인별로 R/G1/G2/B 평면을 독립 분석합니다. 색 응답 차이를 노이즈로 합산하지 않습니다.

- 암영상/밝은 영상의 `(A−B)/√2` 잔차 히스토그램, Gaussian 비교, 표준화 잔차와 3σ 꼬리 통계. 픽셀 평균을 뺀 잔차도 NPZ에 저장합니다.
- 픽셀별 오프셋·읽기 노이즈 RMS·분산·변환 게인 분포와 지도, 높은 노이즈 픽셀 마스크, 게인 피팅 R²/사용 단계 수.
- DN 및 검증된 전자 단위의 PTC: 시간 노이즈, shot noise, 읽기 노이즈, 노출시간에 맞춘 암노이즈, FPN, 열 FPN, 픽셀 FPN, 공간 패턴을 포함한 전체 노이즈.
- 분산–평균 곡선, 변환 게인 피팅과 제외 단계, 노출시간 응답 선형성, 암신호 증가/검출 가능한 암전류, 행·열 패턴.
- SNR 및 전자 기준 상대 SNR. 카메라별로 실제 광원 파장의 QE를 입력하면 광자 기준 상대 SNR과 입사 광자 단위의 카메라 비교도 생성합니다. QE 예시값은 실제 측정값이 아니며 사용자가 검증한 값을 입력해야 합니다.
- 픽셀 맵의 이론 표준오차, 독립된 홀수/짝수 프레임으로 얻은 맵 차이의 경험적 정밀도. 기본 100장/단계의 게인 맵은 논문 그림 6의 1,000장/단계보다 불확도가 큽니다.
- 시간에 따른 프레임 평균, 자기상관, 조명 변동, 주파수 스펙트럼. FFT는 중앙 샘플 간격을 사용하므로 불균일한 수신 시각에서는 정밀 광원 주파수 측정으로 해석하지 않습니다.
- 모든 카메라·게인의 PTC/SNR/rSNR 비교. **다른 측정과 비교**에서 다른 완료 세션의 `analysis/report.json`을 선택하면 게인·파장 등 조건을 바꿔 얻은 측정도 함께 비교합니다.

자동 곡선 모드는 카메라·게인마다 11개 그래프와 전체 비교 그래프를 생성합니다. 고정 명암 모드는 7개 분포/성분 그래프와 저장 DN 단위 비교를 생성합니다. 결과는 `noise_sessions/noise_.../analysis`에 PNG/SVG, 곡선 CSV, 픽셀 맵·잔차 NPZ, `report.json`, 브라우저에서 볼 수 있는 `report.html`로 저장됩니다. 각 촬영 지점의 `.raw`는 메타데이터의 `<u2`, `stored_shape`, `count`로 읽는 연속 프레임 스택입니다. 원래 ADC 정렬을 변경하지 않으므로 DN은 **저장된 RAW DN**이며 변환 게인은 이에 대응하는 DN/e− 또는 e−/DN입니다. 카메라별 실제 노출시간/게인, ADC, 처리 상태, CFA, ROI, FrameID, chunk, CRC/전송 상태 및 시각도 남깁니다.

### 계산·유효성·논문과의 관계

기준 문헌: [Li et al. (2016), *Assessing low-light cameras with photon transfer curve method*](https://doi.org/10.1142/S1793545816300081). [공개 원문](https://www.researchgate.net/publication/301673488_Assessing_low-light_cameras_with_photon_transfer_curve_method)의 §2.3, §3.1–3.3, 그림 5–7을 토대로 구현했습니다. 그림 6은 256×256 부분 영역, 16개 조건(암영상 포함), 조건별 RAW 1,000장을 사용합니다. 프로그램의 자동 곡선 모드는 §2.3의 단계별 100장과 §3.1의 최단 차광 1,000장을 사용합니다. 그림 6 전체의 동일한 실험을 재현했다고 표시하지 않습니다.

자동 곡선 모드는 두 번의 사용자 조작으로 수행하기 위해 **고정 광원에서 노출시간을 순회**합니다. 논문의 **고정 노출시간에서 광량을 바꾸는 실험**과 구별하며, 이 차이는 결과 메타데이터/보고서에도 명시합니다. 노출시간에 따른 암전류 영향을 줄이기 위해 각 노출시간·게인별로 별도의 암영상 평균과 분산을 차감합니다. 같은 고정 게인끼리만 변환 게인을 추정합니다. 이 순회 방식과 노출시간별 암영상 필요성은 [EMVA 1288 §6.3](https://www.emva.org/wp-content/uploads/EMVA1288-3.1a.pdf)의 방법 I에 설명되어 있습니다. 이 기능 자체가 EMVA 준수 인증을 의미하지는 않습니다.

픽셀 시간 분산은 `N−1`의 불편 추정량을 사용합니다. 독립 프레임 쌍의 차이를 √2로 나누어 고정 패턴을 제거하고, 암영상의 분산을 차감해 shot variance를 추정합니다. 전역/픽셀 변환 게인은 `Σ(signal×shot variance)/Σ(signal²)`로 구합니다. 포화·조명 변동·불충분한 단계·음수/비선형 피팅은 제외합니다. 전역 shot-noise 피팅 R²≥0.9, 노출시간 응답 R²≥0.99를 요구하며, 픽셀 게인도 사용 단계 3개 이상과 R²≥0.9를 요구합니다.

밝은 노이즈 촬영은 최장 노출시간에서 먼저 빛이 실제로 들어오는지 확인합니다. 계속 암영상 수준이면 캡 제거 안내와 함께 긴 촬영 전에 중지합니다. 최단 노출시간의 신호가 약한 정상 단계는 별도로 보존합니다. 이후 32장(필요하면 최대 96장)으로 안정된 조명 구간을 검사합니다. 사전 검사 장수는 실험의 100장/1000장에 포함하지 않습니다. 판정 기준을 고정한 뒤 LED 소등, 밝기 변화, CFA별·영역별 밝기 띠, 간헐적 포화 프레임을 제외하며, 카메라 중 하나라도 실패한 촬영 묶음은 모두 제외하고 부족한 정상 장수를 자동 보충합니다. 노출시간·게인·RAW 값은 변경하지 않습니다. 가능하면 256×256 분석 ROI 바깥의 별도 픽셀로 조명을 검사하여 분석 픽셀의 노이즈 잔차를 골라내지 않습니다. 전체 센서/작은 영상은 ROI 자체를 검사하며 선택의 통계적 영향을 보고서에 명시합니다. 결과는 선택된 안정 조명 구간의 조건부 측정입니다.

정상 장수의 30배 시도, 연속 256회 제외 또는 시간 한도에 도달하면 중지하며 차광·미완료 RAW·조명 검사 기록을 보존합니다. 촬영 후에도 ROI의 조명 변동을 재검사하며, 샷 노이즈의 유한 표본 오차를 고려한 하한이 허용치 0.1%를 넘으면 밝은 촬영 완료로 표시하지 않습니다. 실제 RAW가 명목 상한보다 몇 ADC 코드 아래에서 잘리는 경우도 검출하기 위해 99.5% 이상 픽셀 비율을 별도로 계산합니다. 이는 포화 경고이며 정확한 센서 포화용량 측정과 구별합니다. 가장 짧은 노출시간부터 계속 포화되면 조명 강도/조리개를 조절해야 합니다. 차광이 양수 DN 하한에 몰리고 블랙 레벨 클램핑이 켜진 경우 센서 고유 읽기 노이즈의 과소평가 가능성도 표시합니다.

`illumination.json`에는 사전 검사와 모든 정상/제외 프레임의 ID, 시각, 조명 측정값, 카메라별 이유, 보충 장수 및 고정 기준을 기록하고 SHA-256으로 검증합니다. 실패 기록은 `illumination_failed.json`입니다. 완료 결과에서도 **② 밝은 재촬영 · 차광 재사용**으로 기존 결과를 보존하고 검증·복사한 차광과 새 밝은 촬영을 결합할 수 있습니다.

FPN은 암영상 평균을 뺀 밝은 평균 영상의 공간 분산에서, 유한한 밝은/암영상 반복 수에 따른 평균 추정 분산을 차감합니다. 시간 분산과 공간 FPN 분산을 합한 전체 노이즈와 시간 노이즈를 따로 표시합니다. 이는 인쇄된 식 (14)가 픽셀별 시간 평균을 중심으로 삼아 고정 공간 패턴을 제외하는 문제를 명확히 구분합니다. 식 (18)의 부호와 달리 열 FPN은 전체 FPN의 성분이므로 `pixel FPN² = FPN² − column FPN²`를 사용합니다. 조명/렌즈 불균일은 센서 FPN과 구별할 수 없으므로 공간 균일도가 99% 미만이면 FPN/PRNU를 센서 고유값으로 표시하지 않고 해당 한계를 알립니다.

전자 단위는 변환 게인 검증에 성공했을 때만 표시합니다. 포화를 실제 관측한 채널만 **유효 포화용량**과 DR을 추정하며, ADC 포화와 센서의 물리적 full-well limit은 별도 구분할 수 없음을 명시합니다. 미포화 채널은 측정 범위의 하한만 기록합니다. QE·절대 광자량·파장별 광원 설정은 프로그램이 측정하지 않습니다. 알려진 QE 없이 광자 기준 rSNR을 만들어 내지 않습니다. 암전류는 암신호 증가 기울기가 회귀 표준오차의 3배를 넘을 때만 검출값을 표시합니다.

차광과 밝은 촬영의 카메라·ROI·ADC/RAW 처리·실제 노출시간·게인이 다르면 결합을 거부합니다. 불완전 프레임·CRC/설정/FrameID 검사와 재시도는 기존 RAW 획득 경로를 사용합니다. RAW 스택은 저장 직후 SHA-256으로 다시 읽어 확인하고, 모든 스택/메타데이터/통계 및 그래프/결과 파일도 검사합니다. 두 단계와 분석이 모두 완성되기 전에는 `.partial` 폴더로 유지합니다. 중지·실패한 데이터는 보존하되 분석에는 사용하지 않으며, 완료된 차광 단계는 밝은 촬영 재시도에서 재사용합니다. **이전 측정 열기**로 완료된 차광에서 밝은 촬영을 이어가거나 완료 결과를 재검사할 수 있습니다.

USB 이더넷을 실행 후 연결하거나 카메라 전원을 다시 켜도 검색 버튼은 SDK의 인터페이스와 카메라 목록을 함께 갱신합니다. 유선 IPv4 준비 및 초기 빈 검색 결과는 재검색 시간 동안 기다립니다. 검색 중 자동 포커스 이동과 상태 갱신으로 설정 패널이 이동하지 않으며 사용자의 휠 스크롤은 계속 동작합니다.

동일한 실제 카메라 GUI의 중복 실행은 기존 창을 활성화합니다. 두 RAW Rig 실행본이 같은 카메라의 제어권을 경쟁하지 않도록 프로세스 잠금과 로컬 창 활성화를 사용합니다. 가상 카메라 모드는 별도로 실행할 수 있습니다.

자동 노이즈 곡선 촬영은 장시간 촬영 전에 16개 설정을 실제 센서에 적용하고 반올림된 값을 다시 설정해 검증합니다. 요청값과 카메라별 실제 값을 모두 기록하며 RAW chunk는 검증한 실제 값과 대조합니다. 미완료 차광을 다시 시작하면 완료 지점을 검사해 재사용합니다. 예전 버전의 체크포인트 없는 지점은 RAW에서 모든 통계를 재계산해 저장된 통계와 대조합니다. 손상·조건 불일치 지점은 재사용하지 않습니다. 기존 자료를 보존하고 새 세션에서 나머지 단계를 촬영합니다.
